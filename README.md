# ai-translation-provenance

**为 AI 辅助翻译建立可追溯、可核查的记录。**

本项目保存译本的来源信息、翻译运行记录和原文与译文之间的差异记录，不托管第三方作品的原文或完整译文。

## 项目记录什么

- **书目与版本**：书名、作者、采用版本、范围、文件校验值及其他必要元数据。
- **翻译过程**：每次运行使用的 harness、模型、强度、提示词、输入输出校验值，以及人工修订情况。无法核实的信息应明确标记，不作推测。
- **译文差异**：按统一类别记录位置、依据与说明，并标明审计覆盖范围和未完成部分。

## 差异分类

项目使用八类差异，并按核验方式分为结构类与语义类：

| 组别 | 类型 | 判定依据 | 核验方式 |
|---|---|---|---|
| 结构类 | `编译` · `增补` · `省略` · `结构调整` | 段落或章节的边界、数量、顺序 | 对照页面版面和位置 |
| 语义类 | `直译` · `意译` · `误译` · `术语选择` | 具体词句及其含义 | 回看原始页面，不能只依赖 OCR 文字层 |

类型定义和核验规则见 [差异分类规范](spec/差异分类.md)。不要自行增加分类，以免不同书目的记录失去可比性。

## 目录约定

每本书使用独立目录，目录名采用稳定的书目 ID：

```text
books/<book-id>/
├── meta.yaml                  # 书目、版本、范围及文件校验值
├── runs/                      # 每次翻译或审计的运行溯源记录
├── prompts/                   # 实际使用的提示词及版本
├── diffs/differences.yaml     # 结构化差异记录
└── 差异说明.md                # 面向读者的审计摘要
```

`runs/` 按操作分别记录翻译、审计等运行，不把不同阶段混写成一次。运行记录至少应说明 harness、模型与强度、日期、输入版本、提示词或审计方法、输出以及无法核实的事项。

## 新增书目的基本步骤

1. 确定原文版本、处理范围和章节结构，并记录原文文件的 SHA-256。
2. 在翻译前选择翻译目标，明确段落、术语、脚注等处理约定，并保存实际使用的提示词。
3. 每次生成或审计分别建立运行记录；完整原文和译文保存在本机的 `private/` 目录。
4. 逐章核对结构差异；若审计语义差异，必须回看原书页面核实词句。
5. 更新差异数据与摘要，写明覆盖范围、计数口径、未审内容和证据限制。
6. 提交前检查仓库中没有全文，并确保元数据、差异数据和摘要彼此一致。

目前仓库提供分类规范和单书记录示例；**尚无通用新书模板、正式数据 schema、翻译/审计工具或自动校验器**。因此新增书目需参照目录约定手动建立，不能把人工流程描述成可自动复跑的工具链。

## 全文与隐私边界

完整原文和完整译文不提交到仓库。仓库只保存必要的元数据、校验值、运行溯源和差异记录；`private/` 目录由 `.gitignore` 排除。公开任何作品内容前，应先确认相关权利和许可状态。
