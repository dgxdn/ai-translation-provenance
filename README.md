# ai-translation-provenance

**给 AI 译本记录「它是怎么来的」和「它和原文差在哪」。**

不是「AI 译本仓库」——这里没有原文与译文全文。仓库放的是：
一本样本书的**差异数据**、**译本溯源记录**、以及**差异怎么分类的定义**。

## 为什么要记录

当前的 AI 已经能把一本外文书翻译得相当好，在许多段落上比市面上的低质译本
更准确、更通顺。所以问题不在于「AI 翻不了书」，而在于翻完之后：

- **它是哪个模型翻的、依据哪个版本、用的什么提示词？** 通常没人记录。
  于是几个月后你无法判断一个译本的某句话该不该信。
- **它和原文到底差在哪？** 通常也没人记录。于是无法回答
  「这一版比上一版好在哪」，也无法指出某处偏离是有意为之还是失误。
- **「这里翻错了」这句话本身也是模型说的。** 没有交叉验证，
  审查就只是换一个模型讲故事。

这个仓库做的就是这三件事的最小记录方式。

## 差异怎么分类

八类，分两组。**这个分组不是修辞，它决定核验方式**：

| 组 | 类型 | 判定依据 | 怎么核验 |
|---|---|---|---|
| **结构类** | `编译` · `增补` · `省略` · `结构调整` | 段落数、段落顺序 | 数段落、对位置即可，**不依赖字词识别** |
| **语义类** | `直译` · `意译` · `误译` · `术语选择` | 具体字词 | 会被扫描件的文字识别错误污染，**必须回原书页面核对** |

| 类型 | 含义 |
|---|---|
| `直译` | 语义与句式均贴近原文 |
| `意译` | 语义等价，表达重写 |
| `编译` | 合并或拆分原文段落 |
| `增补` | 原文没有的内容 |
| `省略` | 原文有而译文无 |
| `误译` | 语义错误 |
| `术语选择` | 偏离通行译法 |
| `结构调整` | 段落或章节重排 |

这个区分的实际用处：全书约 430 个段落，但**需要回页核对的只有语义类**，
不必均摊到全部段落。

详见 [spec/差异分类.md](spec/差异分类.md)。

## 数据在哪

```
books/the-human-use-of-human-beings/
├── meta.yaml                 # 书籍与译本的基本信息、公版状态、文件校验值
├── runs/                     # 译本溯源：谁、何时、哪个模型、哪个提示词

└── 差异说明.md                # 面向读者的差异说明
```

### 这本样本书

| 项 | 值 |
|---|---|
| 书 | *The Human Use of Human Beings: Cybernetics and Society*，Norbert Wiener |
| 依据版本 | 1954 修订版正文 |
| 译本 | GLM 直出，未人工修订（模型名 `GLM-5.3-flash`，**未核实**） |
| 差异条目 | 17 条 |
| 覆盖章节 | **12 个标题中的 4 个**（原序、第 I、II、XI 章），其余 8 章无数据 |
| 差异类型 | 只有 `编译` 9 · `省略` 5 · `增补` 3。**语义类全部为零** |

**数据的定位是示例，不是成品。** 覆盖 4/12 章，当前无补齐计划。
它的价值在于展示差异记录长什么样、能揭示什么问题。

### 这份数据揭示的一个真问题

第一章有一个段落合并（原文第 13、14 段并成译本第 13 段），
它造成**其后段落全体错位一格**，直到章末第 31 段才复位。

后果：任何按「第 n 段对第 n 段」做的自动比对，**在第一章第 13 段之后全是错的**。
而按顺序对齐的路径本身仍看起来正常——**顺序对齐不能保证对齐正确**。

这条记录在 [differences.yaml](books/the-human-use-of-human-beings/diffs/differences.yaml)
的 `I-m01` 条目里。

## 关于「误差」的两条原则

**一、记录偏离，不要掩盖。** 差异数据里如实记着：语义类判定完全没做、
8 章没有数据、模型名未核实。这些都不藏在措辞里。

**二、字词类结论必须回页核对。** 原书是扫描件，其文字层不可完全信赖。
抽样比对发现词级错误与行序错乱，并已确认数处「可见页面与文字层不一致」——
例如 p88 肉眼为 `flight conditions`，文字层给出 `Hight conditions`。
若直接用抽取文本判定误译，会把扫描缺陷误报为翻译错误，
而假阳性与真阳性看起来完全一样。

**这就是本仓库没有一条「误译」结论的原因**——不是遗漏，是规则的结果。

## 全文为什么不在这里

本仓库**不托管**任何第三方版权作品的原文或完整译文。

仓库只保存：差异数据、溯源记录、规范、以及少量必要的短引句。
原文与译文全文留在项目所有者本地，用 SHA-256 校验值锚定身份。

理由不只是法律风险：**GitHub 无法只删除仓库中的单个文件**。
若投诉声称「整个仓库侵权」，平台会跳过整改步骤直接**整仓禁用**。
把全文与积累的数据放在同一个会被整体删除的容器里，等于让后者陪葬。
