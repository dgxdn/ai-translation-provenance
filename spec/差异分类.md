# 差异分类

版本：1.0

八类差异的定义，以及一个重要的分组。

## 八类差异

| 类型 | 含义 |
|---|---|
| `直译` | 语义与句式均贴近原文 |
| `意译` | 语义等价，表达重写 |
| `编译` | 合并或拆分原文段落 |
| `增补` | 原文没有的内容 |
| `省略` | 原文有而译文无 |
| `误译` | 语义错误 |
| `术语选择` | 偏离通行译法 |
| `结构调整` | 段落或章节重排 |

**不要发明新类型。** 新增类型会让跨书比较失去意义，
而可比性是这个分类存在的理由。

## 一个重要分组

八类分两组。**这个分组不是修辞，它决定怎么核验。**

| 组 | 类型 | 判定依据 | 怎么核验 |
|---|---|---|---|
| **结构类** | `编译` · `增补` · `省略` · `结构调整` | 段落数、段落顺序 | 数段落、对位置即可，**不依赖字词识别** |
| **语义类** | `直译` · `意译` · `误译` · `术语选择` | 具体字词 | 会被扫描件的文字识别错误污染，**必须回原书页面核对** |

### 为什么这个区分重要

对同一本扫描书，两组的可靠性**相差很大**：

- **结构类**的判定依据是段落数与位置。这些来自页面坐标，
  即使文字层有识错，段落边界通常仍然可靠。
- **语义类**的判定依据是具体字词。而扫描件的文字层**不可完全信赖**——
  实测已确认数处「可见页面与文字层不一致」的情况
  （例如 p88 肉眼为 `flight conditions`，文字层给出 `Hight conditions`）。

**后果**：如果直接用抽取文本判定误译，会把扫描缺陷误报为翻译错误。
而这些假阳性与真阳性**看起来完全一样**。

这个区分还有一层实际用处：**它让核对成本可控。**
全书约 430 个段落，但需要回页核对的只有语义类，不必均摊到全部段落。

## 「回页核对」指什么

指渲染原始 PDF 页面目视比对，或用第二套文字识别引擎独立抽取同一页，
与现有文字层、可见页面三方比对。

**不得**以「再跑一次同一个抽取工具」充当核对——它读取的是同一个文字层，
错误是相同的。

**代价说明**：回页核对**不需要额外的 AI 模型**。渲染页面后目视比对即可，
是一条可以立刻执行的核验路径。

## 与 `differences.yaml` 的关系

`differences.yaml` 的每条条目都用上表的 `类型` 值。
条目里另有一个 `alignment_confidence` 字段，含义是：

| 值 | 含义 |
|---|---|
| `高` | 原文与译本的段落一一对应，长度比例接近 |
| `中` | 一一对应但长度比例偏差较大，或多段对多段 |
| `低` | 长度比例明显异常，**对齐本身可能有误** |

这个字段记录的是**「段落配对有多可信」**，与「差异判定是否正确」是两回事。
标为 `低` 的条目应优先人工确认。
