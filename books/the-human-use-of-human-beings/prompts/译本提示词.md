# 译本所用的提示词

这本书的 v1 译本由一条提示词直接生成，原样存档在此。
第二版提示词是随后发现的缺陷的修法，附在后面。

**原样存档是有意为之。** 提示词里的缺陷是历史事实，也是该译本
「同一部书内风格漂移」这一特征的可查证原因。删掉缺陷就等于抹掉证据。

---

## v1 —— 实际使用的提示词（逐字）

```
/Grilling 将这本书翻译成中文，保留书本原滋原味的感觉上，让中文读者也能容易理解，避免出现机翻的味道
```

### 已知问题

**1. 无关前缀 `/Grilling`**

开头的 `/Grilling` 与翻译任务无关。在 DSH 环境中该字符串会触发
「拷问用户」技能——其行为是反复质询用户，而不是执行任务。

这条提示词显然复用自别处，前缀是误留的。

**2. 两个要求方向相反，且未给优先级**

| 要求 | 翻译学对应 |
|---|---|
| 「保留书本原滋原味的感觉」 | **异化**（foreignizing）：贴近原文结构与语感，容忍中文生硬 |
| 「避免出现机翻的味道」 | **归化**（domesticating）：优先中文自然，允许重写句式 |

这两者是**相反方向**的约束。提示词把它们并列交给模型，却没有给出优先级——
所以每次遇到两者冲突，模型都只能自行权衡。

这直接解释了该译本的一个实际特征：**同一部书里风格漂移**，
有的段落极直译，有的段落大幅意译合并。

**3. 未指定的关键决策**

以下事项提示词都没有指定，实际都由模型自行决定：

| 未指定项 | 实际产出 | 后果 |
|---|---|---|
| 术语处理 | 自行增补了一张译名对照表 | 属「增补」类差异 |
| 脚注是否保留 | 省略（全书仅 2 处脚注未译） | 属「省略」类差异 |
| 索引是否保留 | 省略，并在末行注明「索引从略」 | 属「省略」类差异，但有显式声明 |
| 分段与合段策略 | 系统性合并部分相邻段落 | 第二、三、四章合并最多；第一章的合并造成下游错位一格 |
| 专名译法 | 自行决定 | 部分可能偏离通行译法 |

## v2 —— 修法（尚未用于任何一次实际生成）

v2 不做「更好的提示词」这种模糊改进，只做一件事：**把矛盾显式拆开**，
并补上 v1 留下的关键决策。

### 使用前提

使用前必须先声明本次采用哪一个目标：

| 目标 | 适用模板 | 适用场景 |
|---|---|---|
| 异化（foreignizing） | 模板 A | 学术用途、需保留原文论证结构、供研究者比对 |
| 归化（domesticating） | 模板 B | 面向普通读者、追求中文可读性 |
| 折中（compromise） | **不允许** | 该值表示「未作选择」，即 v1 的实际状态 |

### 模板 A：异化优先

```
将以下英文段落翻译成中文。

忠实度目标：异化（foreignizing）。
优先贴近原文的句法结构、论证顺序与修辞方式，允许中文读起来不如
本土写作流畅。不要为了让中文更顺而重写句式、合并句子或调整语序。

具体约束：
1. 段落划分必须与原文严格一一对应。原文 N 段译成 N 段，不得合并或拆分。
   若某段确实难以独立成段，在译文中插入 <!-- MERGE-CANDIDATE: <原因> --> 标记，
   但不要实际合并。
2. 术语：首次出现时译作「中文（English）」，其后沿用中文。不要自行增补术语表。
3. 脚注：位置保留，以「[脚注 N]」标记，不要省略也不要翻译。
4. 数字、人名、地名：保留原文形式并在括号内给中文，不要擅自统一为通行译名。
5. 不要添加任何原文没有的解释性内容。若你认为某处需要说明，
   在译文末尾以「[译者存疑] ...」单独列出，不要插入正文。

只输出译文，不要输出说明。
```

### 模板 B：归化优先

```
将以下英文段落翻译成中文。

忠实度目标：归化（domesticating）。
优先让中文读者顺畅理解，允许重写句式、调整语序。

具体约束：
1. 段落划分必须与原文严格一一对应。原文 N 段译成 N 段。
   这是硬约束——允许改写句子，但不允许合并段落。
   确需合并时插入 <!-- MERGE-CANDIDATE: <原因> --> 标记，不要实际合并。
2. 术语：使用中文通行的学术译法。若采用非常见译法，在译文末尾列出。
3. 脚注：位置保留，以「[脚注 N]」标记。
4. 不要添加原文没有的解释性内容。
5. 不要省略任何句子。若认为某句冗余，照译，并在译文末尾以
   「[译者存疑] ...」说明。

只输出译文，不要输出说明。
```

### 与 v1 的差异

| 项 | v1 | v2 |
|---|---|---|
| 忠实度目标 | 两个相反要求并列，未给优先级 | 显式二选一 |
| 段落对应 | 未指定 | **硬约束：N 段对 N 段** |
| 合段处理 | 模型自行决定 | 插入标记，不实际合并 |
| 术语表 | 模型自行增补 | 禁止自行增补 |
| 脚注 | 未指定（实际被省略） | 保留位置并标记 |
| 增补内容 | 未指定 | 禁止插入正文 |
| 无关前缀 | 含 `/Grilling` | 已移除 |

其中最重要的一条是**段落对应硬约束**：v1 的段落合并是造成差异数据里
「下游整体错位一格」的根源。把段落对应设为硬约束之后，
对齐可以退化为「第 n 段对第 n 段」，**对齐问题基本消失**。

代价是：归化目标下强制逐段对应，可能牺牲一部分中文流畅度。
这是一次**有意识的取舍**，不是免费的改进。
